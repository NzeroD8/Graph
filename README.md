# Визуализатор графа зависимостей пакетов (CLI)

Консольный инструмент для анализа зависимостей пакетов менеджера
apt (Ubuntu).

## Общее описание

Приложение написано на Python и использует только стандартную
библиотеку. Менеджеры пакетов и сторонние библиотеки
для получения зависимостей не применяются: файлы `Packages.gz`
репозитория скачиваются по HTTP и разбираются вручную.

Состояние проекта:

| Этап | Что реализовано |
|---|---|
| 1. Конфигурация | Опции командной строки, их проверка и сообщения об ошибках |
| 2. Сбор данных | Получение зависимостей пакета из репозитория Ubuntu |
| 3. Основные операции | Граф зависимостей: BFS с рекурсией, фильтр, циклы, режим тестирования |

Структура проекта:

```
src/          код приложения
tests/        модульные тесты
test_repos/   файлы тестовых репозиториев для режима --test-mode
scripts/      скрипты демонстрации этапов
run.bat       запуск приложения
```

Модули `src/`:

- `config.py` - разбор и проверка параметров командной строки
- `apt_parser.py` - разбор формата `Packages` и полей зависимостей
- `extract.py` - загрузка индексов репозитория и источник зависимостей
- `graph.py` - чтение файла тестового репозитория, построение и вывод графа
- `main.py` - точка входа

## Функции и настройки

### Параметры командной строки

| Опция | Описание |
|---|---|
| `--package` | Имя анализируемого пакета (обязательна) |
| `--repo` | URL репозитория или путь к файлу тестового репозитория (обязательна) |
| `--package-version` | Версия пакета (обязательна) |
| `--release` | Номер или кодовое имя релиза Ubuntu (`24.04`, `noble`), по умолчанию `noble` |
| `--test-mode` | Флаг: `--repo` - путь к файлу описания графа |
| `--filter` | Подстрока: пакеты с ней в имени не учитываются |
| `--output` | Имя файла с изображением графа, по умолчанию `graph.svg` |
| `--ascii-tree` | Флаг: выводить зависимости в виде ASCII-дерева |


### Проверка параметров


- `--package`: в обычном режиме - строчные латинские буквы, цифры и
  символы `+ - .`, не короче двух символов, первый символ - буква или
  цифра. В режиме тестирования - заглавные латинские буквы;
- `--repo`: в обычном режиме - URL вида `http(s)://хост/путь`. С
  `--test-mode` - существующий читаемый файл.
- `--package-version`: начинается с цифры, допускаются
  буквы, цифры и символы `. + ~ -`.
- `--release`: номер из списка известных (`20.04` ... `26.04`) или
  кодовое имя строчными латинскими буквами. Номер заменяется
  кодовым именем (`24.04` -> `noble`), так как в адресах репозитория
  используются кодовые имена.
- `--output`: только имя файла с расширением `.svg`.
- `--filter`: латинские буквы, цифры и символы `+ - .`.

### Получение данных из репозитория

1. По `--repo` и `--release` строятся адреса файлов `Packages.gz`:
   `<repo>/dists/<релиз>[-updates|-security]/<main|universe>/binary-amd64/Packages.gz`.
2. Файлы скачиваются (`urllib`), распаковываются (`gzip`) и читаются
   построчно. Из каждой записи берутся имя, версия и поля `Pre-Depends`
   и `Depends`.
3. Из зависимостей извлекаются только имена пакетов: ограничения
   версий (`>= 2.34`), архитектуры и условия сборки
   отбрасываются, все альтернативы попадают в список, повторы
   убираются.
4. Для корневого пакета берётся запись с версией `--package-version`,
   для остальных - последняя найденная запись. Зависимость, которой нет
   в индексе, считается пакетом без
   зависимостей.


### Построение графа

- Обход в ширину (BFS), реализованный рекурсивно: функция обрабатывает
  один уровень и вызывает себя для следующего.
- Пакеты, в имени которых есть подстрока `--filter`, не учитываются:
  они не попадают в граф ни узлами, ни рёбрами, их зависимости не
  обходятся. Корневой пакет не исключается никогда.
- Циклические зависимости обрабатываются корректно: 
  каждый пакет раскрывается один раз, а обратное ребро остаётся в графе.


### Режим тестирования

С флагом `--test-mode` вместо URL в `--repo` указывается путь к файлу
описания графа. Пакеты называются заглавными латинскими буквами,
`--package-version` в этом режиме не используется.

Формат: одна строка на пакет, `ИМЯ: зависимости` через пробел или
запятую; `ИМЯ:` - пакет без зависимостей. Пакет без собственной строки -
пакет без зависимостей.

```
A: B C
B: D
C: D
D:
```

Ошибки файла (неверная строка или имя, повторное описание, отсутствие
корневого пакета) выводятся с номером строки. Готовые файлы лежат в
`test_repos/`: `diamond.txt`, `chain.txt`, `cycle.txt`, `complex.txt` и
`broken_syntax.txt`.

### Коды возврата

| Код | Значение |
|---|---|
| 0 | Успех |
| 2 | Ошибка параметров командной строки |
| 3 | Ошибка получения данных (репозиторий недоступен, пакет или версия не найдены, ошибка файла тестового репозитория) |

## Сборка и запуск

Сборка не нужна: используется только стандартная библиотека python3.

Запуск приложения:

```powershell
python src/main.py --package nginx --repo https://archive.ubuntu.com/ubuntu --package-version 1.24.0-2ubuntu7
```

Скрипт `run.bat` запускает приложение и передаёт ему все аргументы:

```bat
run.bat --package nginx --repo https://archive.ubuntu.com/ubuntu --package-version 1.24.0-2ubuntu7
```

Скрипты демонстрации по этапам:

- `scripts\1_part.bat` - корректные запуски и обработка ошибок всех
  параметров;
- `scripts\2_part.bat` - ошибки получения данных и выбор релиза;
- `scripts\3_part.bat` - построение графа на тестовых репозиториях и на
  реальном репозитории.

Тесты лежат в `tests/`, на каждый модуль из `src/` приходится один
файл тестов.

Запуск всех тестов:

```powershell
python -m unittest discover -s tests -v
```


## Примеры использования

Граф на тестовом репозитории:

```
$ python src/main.py --package A --repo test_repos/diamond.txt --test-mode --package-version 1
Граф зависимостей пакета A (пакетов: 4):
  A -> B, C
  B -> D
  C -> D
  D -> (нет)
```

Цикл `A -> B -> C -> A` (файл `test_repos/cycle.txt`):

```
$ python src/main.py --package A --repo test_repos/cycle.txt --test-mode --package-version 1
Граф зависимостей пакета A (пакетов: 3):
  A -> B
  B -> C
  C -> A
```

Фильтр: пакет `G` и всё, что достижимо только через него,
исключены (файл `test_repos/complex.txt`):

```
$ python src/main.py --package A --repo test_repos/complex.txt --test-mode --package-version 1 --filter G
Граф зависимостей пакета A (пакетов: 7):
  A -> B, C
  B -> D, E
  C -> F
  D -> (нет)
  E -> H
  F -> H
  H -> (нет)
```

Реальный репозиторий: nginx без пакетов, в имени которых есть `lib`:

```
$ python src/main.py --package nginx --repo https://archive.ubuntu.com/ubuntu --package-version 1.24.0-2ubuntu7 --filter lib
Граф зависимостей пакета nginx (пакетов: 5):
  nginx -> iproute2, nginx-common
  iproute2 -> debconf, debconf-2.0
  nginx-common -> debconf, debconf-2.0
  debconf -> (нет)
  debconf-2.0 -> (нет)
```

Другой релиз Ubuntu (версия из `noble` не найдена в `jammy`):

```
$ python src/main.py --package nginx --repo https://archive.ubuntu.com/ubuntu --package-version 1.24.0-2ubuntu7 --release 22.04
Ошибка: версия 1.24.0-2ubuntu7 пакета «nginx» не найдена в релизе jammy; в нём есть: 1.18.0-6ubuntu14, 1.18.0-6ubuntu14.22
```

Ошибки параметров:

```
$ python src/main.py --package Nginx --repo ftp://host/ubuntu --package-version 1.0 --output graph.png
Ошибка: --package: имя «Nginx» недопустимо: нужны строчные латинские буквы, цифры и символы + - . (не короче двух символов, первый символ — буква или цифра)
Ошибка: --repo: «ftp://host/ubuntu» не похоже на URL: ожидается вид http(s)://путь (для файла тестового репозитория добавьте --test-mode)
Ошибка: --output: имя «graph.png» недопустимо: нужно имя файла с расширением .svg
```

Ошибка в файле тестового репозитория:

```
$ python src/main.py --package A --repo test_repos/broken_syntax.txt --test-mode --package-version 1
Ошибка: строка 2: ожидается вид «ИМЯ: зависимости»
```
